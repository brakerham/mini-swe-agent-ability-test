# 评测协议

## 本基准回答的问题

在固定任务、相同工具权限和预算下，mini-swe-agent 配合 DeepSeek V4 Pro 能否完成可验证的工程修改？这里评测的是模型与 agent 配置组成的整体系统。改变模型、提示词、工具、步数、上下文或重试规则，都会改变被测系统。

任务覆盖金额计算、配置、分页、依赖图、缓存和记录处理。它们提供可运行的小型项目、行为需求和公开测试，要求修改实际代码。验收测试覆盖需求中的正常、边界、错误和兼容行为。六个任务仍然是有限的合成样本，不覆盖大仓库检索、长期维护、真实部署、前端交互或跨团队协作。

## 运行前冻结的条件

在第一次模型调用前，记录并固定以下内容：

1. 本基准的 Git 提交号和任务清单；任务代码与验收测试的摘要。
2. mini-swe-agent 及模型客户端版本、模型标识、API 地址和模型参数。
3. 容器镜像 ID、平台、Python 版本、资源限制和可用工具。
4. 每项尝试的最大步数、单次调用超时、总时长和重复次数。
5. 主指标、失败处理方式和报告范围。

保存配置文件和依赖版本，不能在看见某个任务的失败后单独增加其预算。接口不支持的参数应明确报错或记录为未支持，不得静默切换到其他模型。

模型服务可能更新同一模型名背后的实现。固定模型名并不等于固定权重。结果应同时记录 UTC 时间、服务返回的模型字段（若有）和服务端用量。

## 每次尝试的流程

1. 从对应任务的初始 `candidate/` 创建全新工作目录。
2. 仅提供任务需求、初始代码、公开测试及约定工具。禁止人工提示具体修复位置、提供参考修复或根据验收结果指导 agent。
3. 在没有外网、没有 API 密钥的任务容器中执行 agent 命令。模型调用由主机客户端完成；容器不挂载评测仓库、参考修复、验收测试、Docker socket 或主机 home。
4. 在预算内运行一次完整 agent 轨迹。公开测试可以重复运行，不允许读取独立验收测试。
5. 停止 agent 后收集候选代码与轨迹。允许修改清单中的源码及 `tests/` 下的 Python 测试文件，拒绝符号链接、其他文件改动和越界内容。agent 编写或修改的测试留作证据，不参与自动评分。
6. 在新的干净环境中应用允许的源码变更，再运行原版公开测试和独立验收测试。agent 修改的测试或配置不参与评分。
7. 保存每个测试的结果、终止原因、用量、耗时和补丁摘要，然后继续下一项独立尝试。

评分阶段没有模型参与。参考修复只用于验证评测器，不作为提示提供给被测系统。

## 预算与失败处理

默认模型配置的具体数值见 `configs/deepseek-v4-pro.json`；配置随结果保存。步数和时长是工程限制，不能被当作精确费用上限。即使步数固定，单次请求也可能生成较多 token；超时或中断后，服务端可能已经计费。

没有可靠价格或计费字段时，费用应为 `null` 或未知。可记录服务返回的 token 用量和请求数，但不根据缺失数据推断费用。用户如需硬性费用控制，应在供应商账户设置额度。

达到步数或时长上限的尝试照常进入预定分母，并报告其终止状态。模型错误、容器错误、评分器错误须单独列出，不能算作成功，也不能从报告中悄悄删除。修复评测基础设施后如需补跑，应公布原因，保持原始记录，补跑整个受影响批次或事先定义的范围。

## 重复次数与比较

建议每个系统每项至少三次独立尝试，使用预先固定的重复次数。每次从初始代码和新对话开始，不继承上一轮的补丁、轨迹或失败分析。比较系统时保持任务、预算、工具、提示词和评分器一致。

主要报告所有任务与重复尝试的 resolved rate，同时列出每项任务的每次结果、部分分、用量、耗时与异常。不能用“最好一次”替代完整结果，也不能将多次尝试中任选一次成功写成单次成功率。小样本的差异不宜做强结论，报告比例时保留分子和分母。汇总中的 Wilson 区间只是描述性辅助量；重复尝试共享相同任务，不满足彼此独立的假设，不能据此推断对所有工程任务的能力区间。

## 污染与隔离边界

验收测试和参考修复随仓库公开，任何已经见过仓库、受其训练或在评测前阅读过它的系统都可能受到污染。任务容器隔离可以阻止本次运行直接读取评分资料，但不能证明训练数据中没有答案，也无法防止操作者预先泄露。

候选 Python 源码与验收测试在评分子进程内执行。目录隔离和结果核对能防止常见的测试文件替换、跳过或缺失测试被误算成功，但不构成针对恶意 Python 代码的完整防篡改系统。刻意修改测试运行器内存、伪造结果或探测评分进程的行为违反协议；对可能这样做的系统，需要独立审查补丁和轨迹，或采用更强的外部行为评测。

本套件适合透明的开发基准和配置回归比较。严肃的外部能力结论应追加由独立保管者准备、未公开且未供模型接触的任务集；该任务集应保持相同评分规则，并在实验结束后披露足够的复现材料。

## 证据保留

每次尝试保留运行配置、环境信息、任务摘要、候选代码、补丁、测试逐项结果、模型终止信息及轨迹。保存原始失败记录；后续修复和重跑追加新目录。轨迹可能包含代码、命令输出或服务端信息，分享前应人工检查。密钥不得写入配置、候选目录或公开结果。

本基准的离线 CI 和 `selftest` 不产生模型能力分数。只有完成真实模型运行并经过独立评分后，才可报告模型结果。
